# 数据库系统复习笔记

索引的本质是用额外的存储空间和写入成本，换取更少的磁盘页访问。数据库通常把数据组织成固定大小的页，索引的作用是让查询尽快定位到目标页，而不是从头扫描整张表。

B+ 树是最常见的磁盘索引结构。内节点只保存键和子节点指针，叶子节点保存完整的键值项，并通过双向链表串联。因为每个节点能容纳很多键，树高通常只有三到四层，一次点查只需要少量页读取。

B+ 树特别适合范围查询。定位到范围起点后，可以沿着叶子链表顺序扫描，不必回到根节点重新查找。这个性质让 B+ 树在范围扫描、排序和前缀匹配场景中表现稳定。

哈希索引只支持等值查询，无法高效处理范围扫描。它把键经过哈希函数映射到桶，理想情况下一次查找就能定位。但哈希冲突需要额外处理，范围条件也无法利用哈希顺序，因此它通常作为辅助索引使用。

LSM-Tree 采用另一条路线：写入先进入内存表，达到阈值后顺序刷成不可变的 SSTable，后台再通过 compaction 合并文件。所有写入都是顺序追加，因此 LSM-Tree 在写多读少的负载下有很高的吞吐。

LSM-Tree 的核心代价是写放大。同一份数据可能在内存表刷盘、层级合并和底层压缩中被反复重写。写放大越高，磁盘带宽消耗越大，也会间接影响前台写入延迟，所以 compaction 策略是 LSM 引擎调优的重点。

分层 compaction 通过限制每层容量来平衡读写成本。数据从 L0 逐层下沉时，会与下一层重叠的 SSTable 合并。合并频率太低会堆积读放大，频率太高又会增加写放大，工程上通常需要在两者之间折中。

布隆过滤器常放在 LSM-Tree 的读路径上。查询某个键时，先检查布隆过滤器；如果它明确回答“不存在”，就可以跳过整个 SSTable。布隆过滤器允许假阳性但不能假阴性，因此不会漏掉真实存在的数据。

WAL 是保证持久性的重要组件。事务修改先顺序写入预写日志，再修改内存中的页；即使进程在刷脏页之前崩溃，重启后也能根据日志重放已提交的修改。把随机写转成顺序写，也是数据库提升写入性能的常见手段。

B+ 树和 LSM-Tree 没有绝对优劣。读多写少、范围查询频繁时，B+ 树的读路径更短；写入吞吐要求高、能接受后台合并开销时，LSM-Tree 更合适。选型必须结合读写比例、延迟目标和磁盘成本。
