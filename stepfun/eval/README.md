# 量化质量评测

目的：回答题面「量化前后的检索质量变化」。这里只隔离**嵌入质量**：
同一份语料、同一组查询、同一套人工 qrels，用不同 dtype 的权重编码，按 cosine 排 top-10。

- 数据：`data.json`（40 段中文语料 / 20 条查询 / 每条 1–4 个相关段落）。
- 方法：`Recall@k = |相关 ∩ top-k| / |相关|`；`nDCG@10 = DCG@10 / IDCG@10`；
  `MRR@10 = 1/首个相关结果的排名`。对 20 条查询取算术平均。
- 不使用全文臂：应用里的混合检索是固定 RRF，量化的相对差异在纯向量上更干净。
- 不测端侧吞吐：那是浏览器/设备相关数字，页面计时面板单独给。

## 运行

```bash
npm run fetch-model -- --all   # 需要 fp32 / fp16 / int8 / uint8 四套权重
npm run eval
```

输出：`results.json`（含每条查询的 top-5 与指标）、`results.md`（汇总表）。

## 限制（请连同数字一起读）

1. 40 段 / 20 条查询是小样本，0.8 个百分点的差异接近噪声，不能外推成“量化更好/更差”。
2. Node CPU 上的 `ms/段` 只用于四套权重横向比较，不代表浏览器性能。
3. qrels 是作者按语义相关性人工标注的，不是公开 benchmark；语料与标注都在 `data.json`，可复核。
4. 应用实际跑的是 fp16（WebGPU）或 uint8（WASM）；本表同时报告 int8 作为对照。
