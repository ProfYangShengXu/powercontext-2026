运行环境：WSL2 Linux x86_64、Python 3.12.3、seekdb `pylibseekdb 1.4.0.post2`（嵌入式）、

## 1. MiniMax

| 项 | 取值 | 备注 |
|---|---|---|
| 模型 | `MiniMax-Text-01` | 题面指定，实测可用 |
| 端点 | `https://api.minimax.chat/v1` + `/text/chatcompletion_v2` | 由 `MINIMAX_CHAT_PATH` 注入，不写死在适配器 |
| 认证 | `Authorization: Bearer <MINIMAX_API_KEY>` | key 只在 `.env`（gitignore），代码/日志/证据里无 key |
| 请求参数 | `model` / `messages[]` / `stream=false` / `max_tokens` | 输出预算默认 8192 |
| 超时 / 重试 | 60s / 可重试错误最多 2 次退避 | 不可重试：鉴权、参数、额度、模型下线 |
| 错误模型 | **HTTP 200 + `base_resp.status_code != 0` 也是失败** | 适配器先解析 `base_resp` 再看 `choices` |
| 观察到的错误码 | 1002 限流、1004 鉴权、2013 参数/未知模型、1008 余额 | 2013 实测：未知模型返回 200 + 2013 |

调用统计：代码生成 3 次（`evidence/01..03`）+ 业务补丁/重试 17 次（`devlog/*.jsonl` 中 `step=model`）。

调用链（项②）：

```
task.yaml → context pack(JSON+md) → prompt（system 规则 + 任务 + 12 条来源）
  → chatcompletion_v2 → raw reply（整文件或 diff）
  → 语法检查 / difflib 生成 diff → guard_patch（只许 demo_project/shop）
  → git apply → pytest 自检 → 通过才 commit；失败回滚、把测试输出回灌重试
```

devlog 每条 run 记录：`context_sha256`、`prompt` + `prompt_sha256`、`model`、`usage`、`latency_ms`、
`request_id`、`raw_reply` + `reply_sha256`、`patch` + `patch_sha256`、`self_check`、`applied_commit`、
`base_commit`。例：`devlog/final4.jsonl`。

## 2. seekdb（StorePort）

- 嵌入式实例：`pylibseekdb.open(db_dir=MMCTX_SEEKDB_PATH)`，目录必须在本地 Linux 文件系统
  （WSL 用 `/mnt/wsl/mmctx-seekdb`；`/mnt/d` 是 9p，打不开）。
- 表：`mm_doc_chunks`（PRIMARY KEY `chunk_uid`；`VECTOR INDEX ix_mm_vec ... WITH (distance=l2, type=hnsw, lib=vsag)`）；
  元数据表 `mm_meta` 记录实际 FTS parser。当前 46 个当前块、10 个文件、历史版本 3 行（`is_current=0`）。
- 全文：`CREATE FULLTEXT INDEX ix_mm_fts ... WITH PARSER IK`（中文必须 IK/NGRAM；SPACE 会把整段汉字当一个 token，
  所以代码里按 IK→NGRAM→SPACE 降级并把实际 parser 写进 `mm_meta`）。查询用
  `MATCH(searchable) AGAINST(... IN NATURAL LANGUAGE MODE)`。
- 混合召回：**一条 SQL**：fts 子查询 `LIMIT k` UNION ALL vector 子查询 `ORDER BY l2_distance(...) APPROXIMATE LIMIT k`，
  RRF 融合在应用层。`EXPLAIN` 出现 `TEXT RETRIEVAL SCAN` 与 `VECTOR INDEX ADAPTIVE SCAN`（`docs/explain.txt`）。
- 规格换代：块身份含内容 hash；同 `doc_id` 重导入时旧块在同一事务里 `is_current=0`，检索硬带 `is_current=1`。
- 运行期问题：seekdb 默认 `ob_query_timeout=10s`，冷启动建 HNSW / 首次批量写 46 条向量会报 4012，
  适配器在连接后设 `ob_query_timeout=60000000`（60s）。HNSW 是增量构建，写入后先 `warm_vectors()` 推到稳定，
  未就绪时 `context` 以 exit 8 失败而不是返回部分结果。

## 3. PowerContext（StatePort）

- 启动：`POWERCONTEXT_HOME=<dir> powercontext server run`（端口 8000，SQLite，`ACCESS_MODE=disabled`，MCP 关闭）。
  本机用 `POWERCONTEXT_HOME=/mnt/wsl/pc-home`。
- 用到的接口：`GET /health/ready`、`GET/POST /v1/scopes`（按标题查找/创建）、
  `POST /v1/sources/content`（每个语料文件登记为 Source，`source_id=f"{doc_id}:{content_hash}"`，
  内容变即新 source，避开 409 幂等冲突）、`POST /v1/memory/remember`、`POST /v1/memory/entries/list`。
- 8192 字节：服务端按 NFC + strip 后的 UTF-8 字节数限制 `text`。校验只发生在适配器
  `pc_state.check_text_limit()`；CLI 超限时按 todo→title 顺序裁剪并写 `truncated: true`。
- 状态模型：`{"task_id","run_id","spec_digest","context_sha256","applied_commit","status","todo","seq","updated_at"}`
  规范 JSON；`load_latest` 取 `seq` 最大者，`save` 若内容指纹相同则不新增记录（幂等）。
- 状态复用证据：`state` 与 `resume` 是两次独立进程；resume 只从 `entries/list` 读，
  输出 `run_id_from_state=final4`、`applied_commit=ad24f11f6`、`todo`、`stale=false`（`docs/state-roundtrip.log`）。

## 5. 交付前修掉的问题（审计 → 修改）

1. `make demo` 在 test-before 处被 make 中止 → test-before 行加 `-`，日志仍记录真实退出码。
2. `run` 用整仓 `git status` 判脏，被自己的 out/devlog 挡住 → 只看 `demo_project`。
3. devlog 没有 context→reply→patch 一条链 → 所有步骤共享 `RUN_ID`，run 记录 context_sha256 / prompt 全文。
4. `expected_sources` 只有会 skip 的测试在读 → 变成 `cmd_context` 的硬判据（缺失 exit 3），并补 `ensure_required`。
5. `run --allow-dirty` 可能把 tests 一起提交 → 只提交 `guard_patch` 的精确路径；`cmd_test` 拒绝测试文件被改。
6. MiniMax 适配器写死 OpenAI 形态 → 改为 v2 端点 + `base_resp` 解析（解析模块由 MiniMax 自己生成）。
7. 弱模型写 diff 不可靠 → 支持「整文件」输出并由 `difflib` 生成 diff；应用后先跑目标测试，失败回滚重试。
8. 事后 `verify` 把历史上下文包判成 hash 不符 → 包记录 `base_commit`，按提交反查；脏工作区退化为按工作区。
9. `state` 按 devlog 文件名找最近 apply，`final` 与 `official` 排序错 → 按记录 `ts` 取最大。
10. 集成测试在缺 PC/seekdb 时静默 skip，绿是假绿 → 本次交付在 PC 与 seekdb 都就绪的机器上跑出
    `37 passed`（`docs/test.log`），`docs/demo-*` 也是真实服务在跑。
