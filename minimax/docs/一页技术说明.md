# 一页技术说明

**做了什么**：一条有证据链的 SDD 上下文流水线。`import` 把规格/代码/测试切块、算内容 hash、写入嵌入式
seekdb 并把每个文件登记为 PowerContext Source；`context` 用**一条 SQL** 同时取全文与向量候选，RRF 融合、
按 kind 保底、补齐任务声明的必需来源，产出一份每条都带 `path:start-end:hash` 的上下文包；`run` 把包交给
MiniMax-Text-01，模型给出完整新文件或 unified diff，守卫只允许改 `demo_project/shop`，应用后**先跑测试**
再提交；`test` 记录命令/退出码/提交；`state` 把任务状态写进 PowerContext，`resume` 在新进程读回。

**为什么这样分层**：变化最快的是端点、SDK 语法、部署形态，最慢的是「这次任务需要哪些规格/代码/测试」。
于是 core 只放选择规则（零外部 import），适配器放会变的东西，`bootstrap/main.py` 是唯一装配点。
三条端口——`StorePort`（seekdb 存资料并检索）、`StatePort`（PowerContext 存状态并跨重启复用）、
`ModelPort`（MiniMax 改代码）——**不合并**：合并会把语义压到最弱公共子集，检索退化成键值查询，
状态退化成不可检索文本，题面三项证据也会变成同一份、无法分别核对。8192 字节、`is_current`、
`max_tokens` 这类实现约束只出现在适配器里，core 不知道。

**四项可机器检查的机制**

1. **来源真实性**：包内每条有 `content_hash`；`verify` 校验路径存在、行号合法、`sha256(文件切片)` 匹配、
   切片与包内正文逐字节相等、`chunk_uid` 在库里 `is_current=1`。包还记录 `base_commit`，事后按提交反查，
   补丁改了文件也不会把旧包判成造假。
2. **规格时效性**：块身份含内容 hash；重导入时同一 `doc_id` 的旧块**同一事务**内置 `is_current=0`，
   查询硬带 `is_current=1`。实测改 S-02 后新句进包、旧句不进；还原后相反（`docs/spec-refresh.log`）。
3. **状态幂等与上限**：状态是规范 JSON，`save` 对相同指纹不新增记录；8192 UTF-8 字节（NFC+strip）
   在适配器内部校验，CLI 超限先裁剪并写 `truncated`。`state`/`resume` 是两个独立进程，
   resume 只走 `memory/entries/list`，读到上一轮 `run_id`、`applied_commit`、`todo`。
4. **失败可见、不降级**：具名退出码 3/4/5/6/7/8/9；关键失败写 devlog；模型补丁应用后自检失败会回滚，
   把测试输出回灌重试；无 diff、打不上、改动测试都算失败，不产出假成功记录。

**MiniMax 的参与是两处，不是一次 ping**：`mmctx/adapters/minimax_payload.py`（121 行整文件）
由 MiniMax-Text-01 分 3 轮生成（含按失败测试修正），证据在 `evidence/`；`demo_project/shop/filters.py`
的功能实现由 final4 那次调用生成（1 次通过），devlog 串起 context_sha → prompt 全文 → raw_reply →
patch_sha → applied_commit，提交 `ad24f11f6`。

**实测数字**：语料 10 文件 46 块（spec 21 / code 8 / test 17），当前库含 3 行历史版本；单次综合关键词召回
1 条 SQL；上下文包 12 条来源、约 966 token；`make test` 37 passed；改前 9 failed/6 passed（AssertionError），
改后 15 passed；`make demo`（final4）全链 exit 0。

**明确没做**：不做完整 Agent 框架（无 planner / 多轮工具循环 / RAG 自评）、不存对话历史（只存任务级状态）、
不做 Web UI、不改 PowerContext 的 `src/`；向量用本地确定性特征哈希作辅助召回（FTS 单路可用即保底），
不依赖在线 embedding 服务。已知限制：模型写 diff 不稳定，所以主路径是「整文件 + 自检重试」；
seekdb 必须放本地 Linux 文件系统；中文全文依赖 IK/NGRAM，降级到 SPACE 时召回会明显变差（已记录 parser）。
